# NoteScript

NoteScript is a portable, deterministic, Markdown-first music composition system.

The core does not contain AI. A NoteScript song is an ordinary `.md` file that can be authored by a person or an external tool, previewed with local sound/instrument add-ons, and rendered to audio.

**License: MIT**

## Core workflow

1. Create or receive a NoteScript `.md` song.
2. Validate it.
3. Preview it with installed sound add-ons.
4. Edit the Markdown or change add-ons.
5. Render the accepted version to WAV.
6. Optionally export MIDI.

This supports the intended ChatGPT workflow without embedding AI in the application: ChatGPT can create/update the `.md`; NoteScript remains the deterministic music engine.

## Portable-first layout

```text
NoteScript-portable/
├─ NoteScript.cmd              # single logic entry point
├─ Studio.bat                  # thin shortcut -> NoteScript.cmd studio
├─ Start.bat                   # thin shortcut -> NoteScript.cmd start
├─ Stop.bat                    # thin shortcut -> NoteScript.cmd stop
├─ Status.bat                  # thin shortcut -> NoteScript.cmd status
├─ Validate.bat                # thin shortcut -> NoteScript.cmd validate
├─ Render.bat                  # thin shortcut -> NoteScript.cmd render
├─ runtime/
├─ app/
├─ projects/
├─ exports/
├─ config/
│  └─ network.json            # single source of truth for Control API host/port
├─ tools/
│  ├─ ffmpeg/                 # optional portable decoder tool
│  └─ fluidsynth/             # optional SF2/SF3 backend
├─ sounds/
│  └─ <SoundPackName>/
│     ├─ pack.md
│     └─ audio files...
└─ instruments/
   ├─ SFZ/
   │  └─ <InstrumentName>/
   │     ├─ instrument.md
   │     └─ .sfz + samples...
   ├─ SF2/
   │  └─ <InstrumentName>/
   │     ├─ instrument.md
   │     └─ .sf2
   └─ SF3/
      └─ <InstrumentName>/
         ├─ instrument.md
         └─ .sf3
```

No installation database is required for add-ons. Copying a folder in installs it; removing the folder removes it.

## Two separate add-on systems

### 1. `sounds/` — NoteScript sample packs

This is the user-defined format discussed for NoteScript itself.

Example:

```text
sounds/WarmPiano/
├─ pack.md
├─ C3.wav
├─ C4.wav
├─ E4.wav
└─ G4.wav
```

Song usage:

```text
sound: WarmPiano
```

A pitched pack maps notes to files:

```notescript-sound
name: Warm Piano
version: 1
author: Your Name
license: CC0-1.0
source: your-source
type: pitched
fallback: nearest

sample C3 = C3.wav
sample C4 = C4.wav
sample E4 = E4.wav
sample G4 = G4.wav
```

A SoundPad maps arbitrary trigger names:

```notescript-sound
name: Forest SoundPad
type: soundpad

trigger kick = kick.wav
trigger shaker = shaker.wav
trigger rain = rain.wav
```

### Built-in free sound library

NoteScript ships a deterministic, redistributable native sound library generated by
`scripts/generate-core-sounds.js`. These packs are authored by the NoteScript project
and distributed under the repository MIT license:

- `piano` — Piano
- `electric-piano` — Electric Piano
- `music-box` — Music Box
- `organ` — Organ
- `synth-bass` — Synth Bass
- `synth-lead` — Synth Lead
- `warm-pad` — Warm Pad
- `pluck` — Pluck
- `soundpad` — 16-pad drums, percussion and effects

The built-in SoundPad currently contains:

`kick`, `snare`, `clap`, `closed-hat`, `open-hat`, `shaker`,
`tom-low`, `tom-high`, `rim`, `cowbell`, `crash`, `ride`,
`chime`, `click`, `laser`, and `impact`.

All of these are generated locally from deterministic synthesis code rather than copied
from a third-party sample library, so the portable build can redistribute them together.

### 2. `instruments/<FORMAT>/` — standard instrument formats

These are kept separate from NoteScript-native sound packs.

Examples:

```text
instruments/SFZ/SalamanderGrandPiano/
instruments/SF2/GeneralUserGS/
instruments/SF3/MyCompressedSoundFont/
```

Song syntax is reserved as:

```text
instrument: SFZ/SalamanderGrandPiano
```

The add-on manifest must match the parent format folder.

Current baseline can discover and validate SFZ/SF2/SF3 instrument add-ons. The first SFZ subset adapter renders/auditions SFZ directly. SF2/SF3 render and audition through the optional FluidSynth backend when it is available; otherwise those add-ons remain visible but are marked non-playable.

```markdown

```

## Current v0.1 implementation

Implemented:

- Markdown parser/validator.
- Tempo, time signature, key metadata, PPQ.
- Multiple tracks.
- Notes, chords, rests, named triggers.
- Whole/half/quarter/eighth/sixteenth and dotted durations.
- Velocity and track volume.
- Timeline compilation.
- Folder-based `sounds/` add-ons.
- Pitched sample packs with nearest-root pitch shifting.
- SoundPad named-trigger sample packs.
- Built-in MIT sound library with 8 pitched packs and a 16-trigger SoundPad.
- PCM16 WAV loading and deterministic WAV rendering.
- Decoder abstraction with optional FFmpeg support for FLAC/OGG/OPUS/AIFF/MP3/M4A.
- First SFZ subset parser/renderer with key/velocity regions, pitch center, tune/transpose, gain and simple envelope handling.
- MIDI export.
- Windows preview via the default audio player for the legacy CLI preview command.
- In-browser Project Transport preview with Play/Pause/Stop/Seek/Loop and no external player.
- In-memory/cached project preview rendering through the Control API.
- Non-destructive preview volume and stereo pan controls; pan is explicitly left-to-right (`L 100 -> C -> R 100`) and maps to Web Audio `-1 -> 0 -> +1`.
- Browser audio-output selection when the browser exposes Web Audio `setSinkId`.
- Separate SFZ/SF2/SF3 instrument add-on discovery/validation.
- SFZ offline song rendering and SFZ audition-note rendering.
- Optional FluidSynth backend for SF2/SF3 offline rendering and audition-note rendering.
- SoundFont bank/preset selection through `instrument.md`.
- NoteScript Studio with tabbed Play / Project / Compose / Tracks / Sounds / Settings workspaces.
- Game-style Play page with performance HUD, on-key hotkey caps and playable piano/SoundPad controls.
- BeatLane6 rhythm-game mode using NoteScript Markdown projects as level sources.
- BeatLane6 six-lane `A S D | J K L` play with deterministic Easy/Normal/Hard chart generation from the canonical timeline.
- BeatLane6 pre-roll highway, Tap/Hold/chord input, Perfect/Great/Good/Miss judgement, combo multiplier, score, accuracy, life/fail and success results.
- BeatLane6 hit audio uses the source track's real NoteScript sound/instrument; an optional low-volume full-song guide track is available.
- Bundled `BeatLane6 Starter.md` project teaches all six lanes with the Pluck sound pack.
- Browser-based live playing: mouse keys, remappable computer-keyboard controls, polyphony, velocity, octave shift, sustain and panic.
- Direct piano hotkey edit mode: click a mapped piano key, press its new keyboard binding, then Save or Cancel; current bindings remain visible as faint keycaps beside note names.
- SoundPad controls use the same game-style hotkey model: each pad shows its trigger name plus a faint current hotkey, keyboard hotkeys can trigger pads directly, and Edit Hotkeys works from the pad itself.
- SoundPad has per-pad volume mixing from 0–100%, persisted per sound-pack ID, plus RESET MIX to return the current SoundPad to 100%.
- SoundPad MIX LOCK is enabled by default for every SoundPad. It persists per sound-pack ID and protects all pad-volume sliders plus RESET MIX while keeping pad playback and hotkeys active.
- Piano note/hotkey labels are centered inside the actual white/black key bounds rather than relying on browser static-position behavior.
- Optional Web MIDI input for note on/off, velocity, sustain and all-notes-off.
- Project create/open/save/rename/delete flow inside the portable workspace.
- Compose Text / Form / Node modes editing the same authoritative Markdown project.
- Node palette plus Bar/Event Node Inspector with edits written back to Markdown before Save.
- Advanced multi-track arrangement view with synchronized per-track stems.
- Advanced Play/Pause/Stop/Seek plus per-track Mute/Unmute that works during playback.
- Separate Sound Pack and Instrument browsers.
- Persistent SF2/SF3 live playback through one FluidSynth process with direct WASAPI output on Windows.
- Safe SoundFont switching, live status, sustain CC and process cleanup.
- Portable `NoteScript.cmd` as the single entry point for Studio, background Control API start/stop, and CLI commands.
- Double-clicking `NoteScript.cmd` opens Studio and starts the Control API hidden in the background when needed.
- `NoteScript.cmd start` and `NoteScript.cmd stop` control only the NoteScript server belonging to that portable folder and are idempotent.
- `NoteScript.cmd status` reports RUNNING/STOPPED, PID, configured URL and API health.
- Convenience `.bat` files are thin wrappers only; all server/network/CLI logic remains in `NoteScript.cmd`.
- Portable folder builder with bundled Node runtime.
- Local Control API intended for GUI, MCP, and ChatGPT Plugin adapters.
- Automated tests.

## Control API

Run:

```powershell
npm run control
```

Network binding is configured in exactly one file:

`config/network.json`

Default:

```json
{
  "host": "127.0.0.1",
  "port": 19427
}
```

The Control API and the single `NoteScript.cmd` entry point both read this same file. Change the IP or port there only; Studio opens the corresponding URL automatically. If `host` is `0.0.0.0` or `::`, the server binds broadly while the local Studio launch path uses the matching loopback address for the browser.

- `GET /` — NoteScript Studio UI

- `GET /v1/capabilities`
- `GET /v1/projects`
- `GET /v1/project`

- `GET /v1/sounds`

- `GET /v1/instruments`

## Free instrument libraries

The architecture is designed to wrap freely licensed libraries rather than bake them into the core. Candidate sources include CC0 sample collections, SFZ libraries such as Salamander Grand Piano, and SoundFont collections such as FreePats. Each imported add-on keeps its own `author`, `license`, and `source` metadata.

NoteScript source code remains MIT; third-party audio assets retain their original licenses.

## Design rules

- Markdown is the source of truth.
- Same input + same sound bytes + same renderer settings should be deterministic.
- AI is external to the NoteScript runtime.
- `sounds/` and `instruments/` are separate systems.
- Standard instrument formats are grouped by format folder.
- GUI, CLI, MCP and ChatGPT Plugin integrations should use stable core/control interfaces.
- Portable paths are relative wherever possible.
- External sound licensing metadata must not be silently discarded.
- MIDI is interoperability, not the primary audio source.
